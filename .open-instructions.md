# Skill: Prevención de Errores Recurrentes (Error Prevention Protocol)

## Propósito
Garantizar que el agente consulte el historial de no conformidades y correcciones pasadas antes de generar código nuevo o parches de depuración, evitando repetir fallos ya resueltos.

## Protocolo de Ejecución Obligatorio

1. **Fase de Análisis (Pre-corrección):**
   - Antes de escribir o modificar código para solucionar cualquier error reportado, busca y lee obligatoriamente el archivo `CORRECTIONS_LOG.md` en la raíz del workspace.
   - Verifica si el error actual comparte similitudes con alguna no conformidad previa registrada.

2. **Fase de Implementación:**
   - Diseña la solución asegurándote de no utilizar los enfoques o patrones fallidos documentados.

3. **Fase de Actualización (Post-corrección):**
   - Una vez resuelto el problema, agrega una nueva fila en `CORRECTIONS_LOG.md` con: ID consecutivo, fecha actual, síntoma, causa raíz y la solución implementada con su respectiva regla a evitar.

---

## Activación Rápida
Cuando el usuario ejecute o invoque `@fix-check` o indique "Corregir error con protocolo", debes responder confirmando que leíste `CORRECTIONS_LOG.md` antes de proponer cualquier cambio.
